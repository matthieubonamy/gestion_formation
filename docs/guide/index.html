Comprendre

Le projet en 1 page

Ce qu'on construit et pourquoi
▼

On construit une application web (une « PWA ») pour gérer une activité de formation. C'est un mini-CRM : un carnet d'adresses intelligent + un suivi des formations + des relances.

PWA = Progressive Web App. C'est un site web qu'on peut installer sur le téléphone comme une appli (une icône sur l'écran d'accueil), qui s'ouvre en plein écran. Pas besoin de l'App Store ni de Google Play.

Ce que l'application sait faire (le MVP)

FonctionÀ quoi ça sert
Connexion adminSeul le formateur entre dans l'app (mot de passe).
PersonnesAjouter / modifier / supprimer / chercher des prospects et clients.
FormationsLe catalogue : nom, prix, dates, statut.
InscriptionsRelier une personne à une formation, suivre présence et paiement.
Mini-CRMDates de relance, priorité, historique.
Tableau de bordLes chiffres clés en un coup d'œil.
Export CSVRécupérer toutes les données dans Excel.

Ce qu'on ne fait PAS au début (volontairement)

Paiement en ligne, espace apprenant, espace formateur, signature électronique, IA, messagerie, app mobile native. On reste simple et utile.

Avec quels outils ?

Next.js (le site + le cerveau), Supabase (la base de données + les mots de passe), Vercel (la mise en ligne). On explique chacun plus loin.

Comptes

Créer ses comptes (gratuits)

GitHub, Supabase, Vercel
▼

Trois comptes gratuits suffisent pour tout le MVP. Utilise la même adresse email partout pour t'y retrouver, et un gestionnaire de mots de passe (ex. le trousseau du navigateur) pour les garder.

1) GitHub — héberge le code

2) Supabase — la base de données + les mots de passe de l'app

Supabase te donne d'un coup : une base de données (le classeur des données), l'authentification (le portier), le stockage de fichiers et des sauvegardes. Gratuit pour démarrer.
⚠️ Sur le plan gratuit, un projet Supabase est mis en pause après 1 semaine sans activité. Il suffit de le réactiver en un clic. Pour une vraie mise en production continue, on passera au plan payant (voir « Coûts »).

3) Vercel — met le site en ligne

Vercel publie l'application sur Internet à partir du code GitHub, automatiquement à chaque modification. C'est le créateur de Next.js.
⚠️ Le plan gratuit (Hobby) de Vercel est prévu pour un usage non-commercial. Pour une utilisation professionnelle réelle, il faut le plan Pro (~20 $/mois). Pour tester, le gratuit suffit. Détails et alternatives dans « Coûts ».
Décisions

Les décisions à prendre

Chaque choix, toutes les options, et ma recommandation
▼

Voici les vrais choix du projet. Pour chacun : les options et ce que je recommande pour un débutant qui veut un résultat simple et pas cher.

⚖️ Décision : Où héberger l'application ?

C'est l'endroit qui rend ton site accessible sur Internet.

Vercel
Le plus simple avec Next.js, déploiement en 1 clic. Gratuit pour tester, Pro ~20 $/mois pour un usage pro.
Netlify
Très proche de Vercel. Gratuit aussi, ~19 $/mois en pro. Bon aussi.
Cloudflare Pages
Gratuit même pour un usage commercial, très généreux. Un peu plus technique à configurer avec Next.js.
✅ Recommandation : Vercel pour démarrer (le plus fluide avec Next.js). Si le budget devient un sujet, Cloudflare Pages est l'alternative gratuite la plus solide.
⚖️ Décision : Base de données + authentification

Où ranger les données et gérer les mots de passe.

Supabase
Base PostgreSQL standard + auth + stockage. Gratuit au début. Données portables (PostgreSQL = standard).
Firebase (Google)
Très populaire aussi, mais base « NoSQL » moins adaptée à nos tableaux reliés, et plus difficile à exporter.
✅ Recommandation : Supabase : mieux adapté à des données reliées (personnes, formations, inscriptions) et tu n'es jamais enfermé.
⚖️ Décision : Acheter un nom de domaine ?

L'adresse de ton site (ex. mon-organisme-formation.fr).

Pas tout de suite
Vercel te donne une adresse gratuite en .vercel.app. Parfait pour tester.
Acheter un domaine
Plus pro et mémorisable. ~5-12 €/an pour un .fr, ~8-15 €/an pour un .com (OVH, Gandi, Infomaniak).
✅ Recommandation : Commence avec l'adresse gratuite. Achète un .fr (pas cher et stable) quand tu présentes l'app à de vrais clients.
⚖️ Décision : Envoyer des emails (relances) ?

Pour envoyer automatiquement des emails depuis l'app.

Aucun au début
Tu relances toi-même par téléphone/email perso. L'app te rappelle juste QUI relancer. Zéro coût, zéro complexité.
Resend
Service d'envoi simple. Gratuit jusqu'à 3 000 emails/mois (100/jour), puis à partir de ~20 $/mois.
✅ Recommandation : Aucun au début. On ajoute Resend seulement quand tu veux automatiser les relances (après le MVP).
⚖️ Décision : Surveiller les erreurs (monitoring) ?

Être prévenu quand l'app plante.

Logs de base
Vercel garde déjà les messages d'erreur. Suffisant pour démarrer. Gratuit.
Sentry
Outil dédié : alertes détaillées. Gratuit jusqu'à 5 000 erreurs/mois, puis ~26 $/mois.
✅ Recommandation : Logs Vercel au début. Sentry plus tard si l'app devient critique.
⚖️ Décision : Un seul admin ou plusieurs ?

Qui peut se connecter à l'application.

Un seul (toi)
Le plus simple. Un compte admin créé à la main dans Supabase.
Plusieurs admins
Toi + ton associé. Supabase gère ça sans surcoût (jusqu'à 50 000 utilisateurs gratuits).
✅ Recommandation : Commence à un, ajoute ton associé quand l'app marche. C'est gratuit et rapide à faire.

Étape 4

Étape 4 — Authentification (connexion admin)

Le portier de l'app
▼

On met une page de connexion et on protège toutes les autres pages.

Comment ça marche (en simple)

  • L'admin tape email + mot de passe sur une page /login.
  • Supabase vérifie, et donne un « jeton » (badge d'entrée) au navigateur.
  • Chaque page privée vérifie le badge ; sans badge → redirection vers /login.
Un middleware est un videur placé à l'entrée : il vérifie le badge avant de laisser voir la page.
⚠️ Ne jamais écrire un mot de passe en clair dans le code. C'est Supabase qui les stocke, chiffrés.

Aller plus loin

Te faire aider par des agents IA

Pour maintenir et améliorer le projet sans rester seul — la vérité, sans bla-bla
▼

Une appli, ce n'est jamais « fini » : il faut la corriger, l'améliorer, l'entretenir. Bonne nouvelle, Franck : tu n'es pas obligé de tout faire à la main. Tu peux te faire aider par des agents IA.

Un agent IA, c'est quoi ? Un assistant à qui tu confies une mission en français (« ajoute un bouton pour exporter les paiements », « répare le test qui plante »). Il va lire ton projet, faire le travail, et te montrer ce qu'il a changé. Claude Code (celui qui a démarré ce projet) en est un.

Ce que tu peux faire concrètement

BesoinComment l'agent t'aide
Ajouter une fonctionnalitéTu décris ce que tu veux, il écrit le code et te l'explique.
Corriger un bugTu colles le message d'erreur, il trouve la cause et propose un correctif.
Comprendre le codeTu lui demandes « explique-moi ce fichier simplement ».
Tâches récurrentesTu peux créer des agents spécialisés : un qui relit le code, un qui répare les tests qui échouent, un qui surveille tes mises en ligne.

Comment démarrer (le plus simple)

Tu peux même aller plus loin et créer des agents qui travaillent en arrière-plan : par exemple un agent qui surveille tes modifications sur GitHub et corrige tout seul quand un test casse. C'est très pratique pour l'entretien au long cours — Matthieu pourra t'aider à mettre ça en place une première fois.

La vérité, sans te mentir

⚠️ Un agent IA est puissant mais il n'est pas magique et il peut se tromper avec aplomb (être sûr de lui tout en ayant tort). Ce n'est pas un pilote automatique : c'est un copilote. Toi, tu restes le chef.

Donc, trois réflexes simples et non négociables :

  • Toujours relire ce que l'agent change avant d'accepter (il te montre tout).
  • Toujours tester avant de mettre en ligne (lance l'app, clique, vérifie).
  • Toujours garder une sauvegarde : fais un export CSV régulier, c'est ton filet de sécurité gratuit.
