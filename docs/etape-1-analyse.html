1. Reformulation du besoin

Nous sommes formateurs. Aujourd'hui, les contacts, les formations et les relances sont gérés de tête, dans un carnet ou dans un tableur. L'objectif est de disposer d'un outil unique qui regroupe tout :

  • les personnes (prospects et clients) ;
  • les formations proposées ;
  • qui est inscrit à quoi ;
  • qui a payé / n'a pas payé ;
  • qui relancer et quand ;
  • un tableau de bord pour voir l'essentiel d'un coup d'œil ;
  • la possibilité d'exporter les données (ne jamais être prisonnier de l'outil).

C'est un mini-CRM spécialisé formation, utilisable sur téléphone comme sur ordinateur — c'est le principe d'une PWA.

PWA = Progressive Web App. Un site web qui se comporte comme une application : installable sur le téléphone (icône sur l'écran d'accueil), s'ouvre en plein écran, fonctionne même avec une connexion faible. Pas besoin de l'App Store ni de Google Play.

3. Architecture : 3 options comparées

Option A — Tout fait maison

Node.js + Express + PostgreSQL, serveur géré soi-même.

✔ Contrôle total, on apprend tout.
✗ Beaucoup à installer, configurer et sécuriser. Trop lourd pour démarrer vite.

Option B — Next.js + Supabase Recommandé

Frontend + backend dans un seul projet, base & auth fournies.

✔ Résultat rapide, peu de plomberie.
✔ Gratuit au début, très bien documenté.
● Dépendance à un fournisseur, atténuée car PostgreSQL est standard.

Option C — No-code (Airtable, Bubble…)

Zéro code.

✔ Très rapide au tout début.
✗ Limites vite atteintes (RGPD, exports, règles, sécurité) et on n'apprend pas à développer.

Recommandation : Option B — Next.js + Supabase + Vercel. Le meilleur équilibre entre rapidité, coût (gratuit pour démarrer), sécurité et apprentissage. On garde notre propre code et nos données restent dans une base PostgreSQL standard, donc portable.

4. Analyse du besoin

Qui utilise l'application ?

Pour le MVP, un seul type d'utilisateur : l'administrateur (le formateur). Pas d'espace apprenant ni formateur séparé — volontairement écarté du MVP.

Ce que l'administrateur fait

  1. Se connecter de façon sécurisée.
  2. Gérer les personnes : ajouter, modifier, supprimer, rechercher, filtrer.
  3. Gérer les formations : ajouter, modifier, supprimer.
  4. Inscrire une personne à une formation.
  5. Suivre chaque inscription : présence, statut de suivi, statut de paiement.
  6. Relancer : date de prochaine relance, priorité, canal, historique.
  7. Consulter le tableau de bord et le tableau des personnes à relancer.
  8. Exporter les données en CSV.

Les données à gérer

  • Personnes : identité, contact, statut, source, notes.
  • Formations : nom, description, type, prix, dates, statut.
  • Sessions : dates concrètes d'une formation.
  • Inscriptions : lien personne ↔ formation + statuts (inscription, présence, paiement).
  • Paiements : ce qui est dû / réglé.
  • Relances (CRM) : date, priorité, canal, statut commercial, historique.
  • Notes : commentaires libres rattachés à une personne.
  • (Plus tard) organisations, formateurs, documents, enquêtes de satisfaction.

Ce qu'on ne fait PAS au départ

Paiement en ligne, espace apprenant, espace formateur, signature électronique, automatisations complexes, IA, messagerie, application mobile native, multi-tenant complexe. Le MVP reste concentré et utile.
